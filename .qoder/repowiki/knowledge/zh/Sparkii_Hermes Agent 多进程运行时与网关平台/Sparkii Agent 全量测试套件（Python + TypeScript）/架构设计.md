测试套件按被测子系统划分为多个顶层子目录：`tests/agent/` 覆盖核心 Agent 运行时（适配器、压缩、上下文引擎、凭证池、会话等）、`tests/cli/` 覆盖命令行交互、`tests/gateway/` 覆盖 Gateway HTTP/WS 服务、`tests/hermes_*` 覆盖 Hermes 状态与 CLI、`tests/tools/`、`tests/skills/`、`tests/plugins/`、`tests/cron/`、`tests/docker/`、`tests/integration/`、`tests/e2e/`、`tests/stress/` 等分别对应工具、技能、插件、定时任务、容器化、集成、端到端与压力场景；`tests/acp*`、`tests/computer_use*`、`tests/tui_gateway*`、`tests/run_agent*` 等覆盖特定子系统。

共享基础设施集中在 `tests/conftest.py`：通过进程级沙箱将 `SPARKII_HOME` 重定向到临时目录、清理所有以 `_API_KEY/_TOKEN/_SECRET/_PASSWORD` 结尾的环境变量、固定 `TZ=UTC LANG=C.UTF-8 PYTHONHASHSEED=0`，并禁止继承 `SPARKII_SESSION_*`，从而保证本地与 CI 行为一致。实际并行执行由外部 `scripts/run_tests_parallel.py` 启动，每个 `.py` 文件在独立 Python 进程中运行以避免跨文件状态泄漏。

`tests-js/` 是独立的 TypeScript 测试工程，使用 Vitest 4.1.10 与 Node 环境，仅包含少量对安装脚本、包配置、桌面权限等的验证测试，通过 `package.json` 中的 `vitest run` 命令执行。

依赖方向单向：测试代码仅依赖被测模块与 `fakes/`、`fixtures/` 下的假实现，不反向引入生产逻辑；各子目录内的 `conftest.py`（如 `acp/conftest.py`、`cli/conftest.py`）提供该子系统的专用夹具，复用根 `conftest.py` 的全局隔离策略。
