- 新增提供商通过向 `PROVIDER_REGISTRY` 追加 `ProviderConfig` 数据类实例来声明，集中维护 id、name、auth_type、base_url、api_key_env_vars、scope 等元数据，而非分散在多处条件分支中。
- 对敏感值（API key、token）一律不直接日志或返回，改用指纹哈希（`_token_fingerprint`）或名称/路径描述，遵循“零凭据泄露”约定。
- 跨进程安全写 `auth.json` 时统一通过 `_auth_store_lock()` 上下文管理器加锁，并在锁内重新加载最新状态后再写入，避免并发覆盖。
- 凭据来源区分严格：`.env` 环境变量、`credential_pool`（带 `source` 标签）、`config.yaml` 镜像三处必须保持一致；删除操作仅移除 `source == env:<VAR>` 的 pool 条目，绝不触碰 OAuth/device-code/manual/borrowed 凭证块。
- 可选/重型依赖（如 `agent.credential_pool`、`sparkii_cli.models`、`utils`）采用函数内延迟 import，避免启动时循环导入或不可用依赖导致整个认证模块初始化失败。
- 错误统一通过 `AuthError` 携带 `provider`、`code`、`relogin_required` 结构化传递，并由 `format_auth_error` 映射为用户可操作的提示文案，区分速率限制、订阅过期、余额不足等不同语义。
