- 每个配置版本迁移封装为独立的 `_migrate_to_N(results, quiet)` 函数，并在 `MIGRATIONS` 元组中按目标版本严格升序注册，由 `run_migrations` 统一驱动执行。
- 迁移步骤内部通过 `_cfg()` 延迟导入 `sparkii_cli.config` 再取用 `read_raw_config`、`_persist_migration`、`get_env_value` 等辅助，避免与 `config.py` 形成循环导入。
- 所有对磁盘状态的修改都经由 `_persist_migration` 持久化，并通过 `results['config_added']` / `results['warnings']` 收集变更摘要供调用方汇总报告。
- 配置读取采用基于 `(path, mtime_ns, size)` 的进程级缓存 + `threading.RLock` 串行化，确保并发线程不会重复解析同一份 YAML。
- 对用户可写的 `.env` 变量维护显式黑名单（`_ENV_VAR_NAME_DENYLIST`），任何匹配名称的写入都会抛出 `ValueError` 并提示编辑 `~/.sparkii/.env` 直接修改。
- 配置项归一化（如 custom provider、extra_headers、base_url）集中在独立函数内完成，并以小写/去斜杠/去空白等标准化后再参与比较或下发到下游客户端。
