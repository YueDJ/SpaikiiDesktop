配置加载、迁移与回退链解析模块由 config.py、config_migrations.py 和 allback_config.py 三个文件组成，管理 Sparkii 的全部用户配置生命周期。

config.py（5500 行）是配置管理的核心模块，处理 ~/.sparkii/config.yaml（全部设置：模型、工具集、终端等）和 ~/.sparkii/.env（API Key 与密钥）两个配置文件。模块提供 sparkii config、sparkii config edit、sparkii config get/set/unset、sparkii config wizard 等 CLI 子命令。配置加载采用深度合并策略：用户配置覆盖默认值（config_defaults.py，4414 行），形成最终生效的运行时视图。load_config() 返回深度拷贝保证线程安全，load_config_readonly()（被 credential_pool.py 等热路径使用）跳过拷贝以降低性能开销。损坏的 config.yaml 会自动备份为 .corrupt.<ts>.bak 文件，同时回退到默认配置继续运行，不会阻断用户操作。模块还管理环境变量文件（.env）的读写，通过 save_env_value() 和 emove_env_value() 实现原子性更新。

config_migrations.py（761 行）实现表驱动的配置版本迁移注册表。每个迁移步骤是一个函数 _migrate_to_N(results, quiet)，从原始的 768 行 if current_ver < N: 阶梯代码重构而来。迁移语义严格保留：current_ver 在迁移运行前一次性计算，每个步骤比较同一个初始值；步骤间通过文件系统观察前序写入（严格升序保证）。为避免循环导入，所有对 sparkii_cli.config 的访问通过 _cfg() 延迟函数实现。支持下限版本 SUPPORT_FLOOR_VERSION = 12（2026 年 7 月设定），低于此版本的配置不再自动迁移，用户需手动运行 sparkii setup 重建或手动设置 _config_version。已移除的迁移步骤包括 v4（工具进度 .env → config.yaml）、v5（时区种子）、v9（清除 ANTHROPIC_TOKEN）。

allback_config.py（102 行）实现回退提供商链的解析逻辑。回退链允许用户配置多个备用模型/提供商，当主提供商不可用时自动切换。配置支持两种格式：allback_providers（新格式，优先级更高）和 allback_model（旧格式，向后兼容）。get_fallback_chain() 合并两个来源，按 (provider, model, base_url) 三元组去重，返回新鲜的 dict 拷贝列表。esolve_entry_api_key() 解析每个回退条目的 API Key（内联 pi_key 或通过 key_env 环境变量名查找），其中 key_env 通过 gent.secret_scope.get_secret 解析以支持多路复用场景下的 profile 感知。
