本模块由三个相互协作的 Python 文件组成，构成 Sparkii CLI 的模型发现与选择核心：
- `model_catalog.py`：负责从远端（默认 `sparkii-agent.nousresearch.com`，失败时回退到 GitHub raw）拉取并校验 JSON 格式的模型目录清单，按 TTL 做进程内缓存 + `~/.sparkii/cache/model_catalog.json` 磁盘缓存，并通过后台线程实现 stale-while-revalidate；对外暴露 `get_catalog()`、`get_curated_openrouter_models()`、`get_curated_nous_models()`、`get_default_model_from_cache()` 等只读 API，对网络失败完全静默降级。
- `providers.py`：作为提供商身份的单一事实来源，维护 `SPARKII_OVERLAYS`（Hermes 专属 transport/auth/base_url 覆盖）、`ALIASES`（人类友好名→规范 ID 映射）、`_LABEL_OVERRIDES`，并在运行时将 models.dev 目录、overlay 与用户 config.yaml 中的 `providers:`/`custom_providers:` 三段数据合并为 `ProviderDef`；提供 `resolve_provider_full()`、`determine_api_mode()`、`host_mandated_api_mode()`、`is_aggregator()` 等解析函数，区分“路由聚合器”与“扁平命名空间转售商”。
- `model_switch.py`：串联上述两层，实现 `/model` 命令的统一解析（`parse_model_flags_detailed` → `ModelSwitchRequest`）、持久化策略决策（`resolve_persist_behavior`）、短别名到 vendor/family 的目录查找（`MODEL_ALIASES` + `models_dev.list_provider_models`）、直接别名（`DIRECT_ALIASES`，支持从 config 动态加载）、模型版本排序（`_model_sort_key`）以及非 agentic 模型警告检测；通过 `ModelSwitchResult` 统一输出结果。
依赖方向：`model_switch.py` → `providers.py` → `agent.models_dev`；`model_catalog.py` 独立于 providers，仅被 model_switch 及上层 picker 调用。三者共同保证 CLI 与 gateway 共享同一套模型选择语义。
