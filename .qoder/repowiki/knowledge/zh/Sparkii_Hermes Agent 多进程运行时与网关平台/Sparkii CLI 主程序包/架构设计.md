以 `sparkii_cli/main.py` 为单一进程入口，启动时按严格顺序执行：先通过 `_startup_fast` / `_early_recovery` 完成 UTF-8 stdio、venv 自愈、Termux/容器检测等零依赖预热；再解析 `--profile/-p` 并设置 `SPARKII_HOME`，加载 `.env` 与 `config.yaml`，初始化集中式日志（`sparkii_logging`）与安全红白名单；随后通过 `subcommands/` 下的 `build_*_parser` 工厂函数将各子命令注册到 argparse 树，由 `main()` 分派到对应处理器。

四个子目录承担横向能力：
- `subcommands/`：每个文件一个子命令组，仅暴露 `build_<group>_parser`，处理器仍驻留 `main.py` 以避免循环依赖。
- `dashboard_auth/`：Dashboard 登录态、Cookie、Token、WS ticket 与中间件，被 dashboard/gateway 入口复用。
- `proxy/`：对外代理服务器（`server.py` + `adapters/nous_portal, xai`），由 `gateway` 子命令拉起。
- `observability/`：基于 JSON Schema 的共享指标契约（`hermes.shared_metrics.v1/v2`），通过 `relay_runtime` 向 Hermes 上报。
- `web_routers/`：FastAPI 路由片段，供 `web_server.py` 挂载。

跨子模块的协作通过共享配置（`config.py`/`managed_scope.py`）、共享认证状态（`auth.py`/`credential_lifecycle.py`）以及进程级单例（如 `active_sessions.py`、`plugins.py`）实现；所有子命令均经过统一的 TTY 守卫、安全审计启动钩子（`security_audit_startup.py`）和 one-shot 退出清理路径。
