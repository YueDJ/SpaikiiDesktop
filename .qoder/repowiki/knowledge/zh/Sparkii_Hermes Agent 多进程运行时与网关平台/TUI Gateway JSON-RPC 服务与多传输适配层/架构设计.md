模块以 `entry.py` 作为 stdio 入口：安装信号处理、启动后台 MCP 工具发现线程、发送 `gateway.ready` 并进入 `stdin.readline` 循环，调用 `server.dispatch` 解析 JSON-RPC 请求。

- 传输抽象 (`transport.py`)：定义 `Transport` Protocol（`write/close`），提供 `StdioTransport`（写 `sys.stdout`）、`TeeTransport`（主通道 + 侧车 WS 广播）和 `WSTransport`（ws.py 中 per-connection 实现，支持 token 帧合并与事件循环安全调度）。通过 `contextvars.ContextVar` 绑定当前请求的 transport，使 handler 代码与 I/O 解耦。
- 核心逻辑集中在 `server.py`：维护全局 `_sessions`、`_methods`、`_pending`、`_answers`、数据库句柄等；用 `concurrent.futures.ThreadPoolExecutor` 将长耗时 RPC（slash/exec、session.resume、billing、model.options、pet.generate 等）路由到工作池，避免阻塞 stdin 读取循环；内置 `_SlashWorker` 持久化子进程用于执行 `/` 命令。
- 方法按职责拆分到 `methods_*.py`（session、config、prompt、tools、complete），通过 `method_ctx.HandlerRegistry` 的 `@method(...)` / `@profile_scoped` 装饰器注册到 `server._methods`，再在 `server` 初始化时挂载。
- WebSocket 接入 (`ws.py`)：提供 `handle_ws(ws)` 协程，复用同一套 `dispatch` 与所有 handler，仅替换底层 transport；对高频 `message.delta`/`reasoning.delta`/`thinking.delta` 做 33ms 合并以降低事件循环唤醒开销。
- 辅助子系统：`slash_worker.py` 为独立子进程；`host_supervisor.py`、`compute_host.py` 管理宿主/计算主机；`git_probe.py`、`project_tree.py`、`render.py`、`synthetic_turn.py`、`turn_marker.py`、`loop_noise.py`、`event_publisher.py`、`method_ctx.py`、`slash_fuzzy.py`、`_stdin_recovery.py` 分别承担 Git 探测、项目树渲染、合成轮次、转轮标记、循环噪声抑制、事件发布、方法上下文注入、斜杠补全模糊匹配、stdin EOF 恢复等功能。
- 依赖方向单向向外：本模块依赖 `sparkii_cli`、`agent.*`、`tools.*`、`gateway.config` 等上层组件，不被其反向引用；跨进程通信统一通过 JSON-RPC over stdio 或 WebSocket，无共享内存。
