Cron 定时任务调度系统为 Hermes Agent 提供 cron 表达式、固定间隔（interval）与一次性（once）三种调度模式，支持 Agent 自主创建、管理、执行与监控定时任务。核心调度循环由 Gateway 守护进程每 60 秒触发一次 `tick()`，通过跨进程文件锁（`fcntl`/`msvcrt`）防止多进程并发执行同一任务。

任务生命周期从创建到执行全程覆盖：`cron/jobs.py` 维护 `jobs.json` 持久化任务定义，`cron/executions.py` 通过 SQLite（`executions.db`）记录每次执行的状态机（claimed → running → completed/failed/unknown），确保执行记录不可变且可审计。系统支持多配置文件隔离——每个 Profile 拥有独立的 cron 存储目录，避免跨 Profile 的配置/凭据泄露。

监控子系统（`cron/monitor.py`）实现了基于哈希比对的变更检测机制：对 monitor_script 或 monitor_url 的输出计算 SHA-256 哈希，仅在内容实际变化时才触发 Agent 执行，避免无意义的 LLM 调用。任务执行结果通过多平台消息回送（Telegram/Discord/WhatsApp 等）投递给用户，支持自定义投递目标与 origin 追踪。

系统还包含生命周期安全守卫（`cron/lifecycle_guard.py`），在任务创建时扫描 prompt 与 script 中是否包含网关生命周期命令（如 `sparkii gateway restart`），防止 Agent 驱动的 SIGTERM-重启死循环。任务建议系统（`cron/suggestions.py`）提供智能推荐：来自 catalog、blueprint、usage 分析或集成连接的自动化提案，经用户确认后才创建真实任务，确保 consent-first 原则。每个任务还配有持久化记事本（`cron/notepad.py`），以 KV 存储携带跨次执行的游标、水位等状态数据。

调度器采用 Provider 抽象接口（`cron/scheduler_provider.py`），内置 `InProcessCronScheduler` 以守护线程运行 60 秒轮询循环，同时支持外部 Provider（如 Chronos）通过 `cron.provider` 配置切换。Provider 接口预留了 `on_jobs_changed`、`fire_due`、`reconcile` 等可选钩子，支持多机部署下的 at-most-once 投递。
