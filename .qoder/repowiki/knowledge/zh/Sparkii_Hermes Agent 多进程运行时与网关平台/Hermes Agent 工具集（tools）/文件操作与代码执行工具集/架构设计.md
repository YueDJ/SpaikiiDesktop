本模块按职责划分为若干相互协作的子系统：
- 抽象层与后端实现：`file_operations.py` 定义 `FileOperations` ABC 及 `ShellFileOperations`，通过调用终端后端的 `execute()` 把一切文件操作表达为 shell 命令，从而兼容 local/docker/ssh/modal/daytona/vercel_sandbox；`file_tools.py` 在其之上封装路径解析（`_resolve_path_for_task`）、工作区根定位（`_authoritative_workspace_root`）、敏感路径拦截、受保护指令文件审批门控，并暴露给上层工具。
- 安全边界：`path_security.py` 提供通用的 `validate_within_dir` 与 `has_traversal_component`；`binary_extensions.py` 集中二进制扩展白名单；`self_repo_guard.py` 通过静态分析 shell 命令（含 heredoc、git alias、sudo/env 包装）检测会改写运行中源码仓库的 git/gh 操作并阻断；`code_execution_tool.py` 用 UDS（本地）或文件 RPC（远程）在子进程中执行 LLM 生成的脚本，仅暴露 `SANDBOX_ALLOWED_TOOLS` 中的 7 个工具，并对子进程环境变量做白名单过滤。
- 并发与一致性：`file_state.py` 维护进程级 `FileStateRegistry`，记录每个 task_id 对文件的读时间戳与全局最后写入者，通过 per-path `threading.Lock` 序列化 read→modify→write 临界区，并在写前检查是否被其他子代理修改。
- 快照与回滚：`checkpoint_manager.py` 使用单个共享 bare git store（`~/.hermes/checkpoints/store`），通过 `GIT_DIR`+`GIT_WORK_TREE`+`GIT_INDEX_FILE` 隔离用户项目目录，按 turn 去重地创建 checkpoint，并提供 diff/list/restore/prune 能力。
- 文档提取：`read_extract.py` 用 stdlib 解析 `.ipynb/.docx/.xlsx`，可选依赖 `anydoc` 覆盖 PDF/Office/OpenDocument/RTF/EPUB，并对扫描型 PDF 用 `pdftotext` 输出覆盖率警告。
- 差异收集：`working_diff.py` 以 `working/staged/all` 三种模式收集工作区 git diff，供 CLI 和 gateway `/diff` 命令复用。
依赖方向：`file_tools.py` → `file_operations.py` → `binary_extensions.py` + `agent.file_safety`；`code_execution_tool.py` 独立并通过 `model_tools.handle_function_call` 反向调度已启用工具；其余模块均为被调用的纯工具库。
