模块以 `browser_tool.py` 为统一入口，负责后端路由（本地 agent-browser CLI、Camofox REST、或 cloud provider 插件）、会话隔离（按 task_id）、SSRF/私有 URL 防护、截图缓存与快照摘要；通过 `agent.browser_registry` + `plugins/browser/<vendor>/` 动态发现并选择 Browserbase / Browser Use / Firecrawl 等云后端。

- 后端抽象：`browser_tool._get_cloud_provider()` 返回 CloudBrowserProvider 实例，`_is_local_mode()` / `_is_local_backend()` 决定走 agent-browser CLI 还是 Camofox 路径；CDP 覆盖由 `BROWSER_CDP_URL` 或 `config.yaml` 的 `browser.cdp_url` 驱动。
- CDP 持久化层：`browser_supervisor.py` 维护每个 task_id 的 `CDPSupervisor`（单线程 asyncio 事件循环 + websockets），订阅 Page/Runtime/Target/Fetch 事件，维护 `pending_dialogs`、`frame_tree`、`recent_dialogs` 并通过 `SupervisorRegistry` 全局注册；注入 JS 桥 (`hermes-dialog-bridge.invalid`) 把 alert/confirm/prompt 转为 XHR，再由 Fetch.requestPaused 拦截成待处理对话框。
- 工具层：`browser_cdp_tool.py` 暴露 raw CDP 调用（支持 target_id 和 frame_id 路由到 supervisor 子 session），`browser_dialog_tool.py` 暴露 `browser_dialog` 供 agent 响应 pending dialog；两者共享 `_browser_cdp_check` 可用性门控。
- Camofox 子模块：`browser_camofox.py` 通过 HTTP REST 调用 camofox-browser 服务实现 navigate/click/type/screenshot/vision 等，`browser_camofox_state.py` 提供基于 profile 的稳定 userId/session_key 用于持久化浏览器配置。
- 依赖方向：tool 层 → browser_tool（路由）→ 具体后端（CLI/Camofox/cloud provider 插件）；supervisor 独立运行 CDP WebSocket 并由 tool 在 snapshot/connect 时懒启动；CDP 工具可反向通过 supervisor 的 `_cdp` 方法对 OOPIF iframe 执行跨域操作。
