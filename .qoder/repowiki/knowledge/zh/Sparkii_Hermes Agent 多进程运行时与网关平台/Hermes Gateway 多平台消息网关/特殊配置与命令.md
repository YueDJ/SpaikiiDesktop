网关进程通过两种方式启动：`python -m gateway.run`（直接运行模块）或 `cli.py --gateway`（通过 CLI 入口）。启动入口位于 `gateway/run.py`，首先执行 `sparkii_bootstrap`（Windows 上配置 UTF-8 stdio），然后加载 `config.yaml` 中 `gateway` 节的完整配置。

核心配置项包括：`platforms` 节定义每个连接平台的启用状态、凭据（通过环境变量或 `secret_scope` 读取）、家庭频道（home channel）和平台特有参数（如 Telegram 的 `bot_token`、Discord 的 `bot_token` 等）；`agent` 节控制 Agent 缓存大小（`agent_cache.max_size`，默认 128）、空闲驱逐 TTL（`agent_cache.idle_ttl_secs`，默认 1 小时）和自动继续新鲜度窗口（`gateway_auto_continue_freshness`）；`streaming` 节配置流式输出传输模式（auto/off/SSE/WebSocket）；`systemd_watchdog_seconds` 启用 Type=notify 心跳。

多路复用 profile 通过 `GATEWAY_MULTIPLEX_PROFILES` 环境变量启用，允许单进程承载多个 profile 的网关实例，每个 profile 拥有独立的密钥作用域（`_profile_runtime_scope`）。`GATEWAY_MULTIPLEX_PROFILES` 空白值视为"未设置"而非 False，防止未填充的 Fly secret 覆盖 config.yaml 的 opt-in。

平台适配器通过 `platform_registry.py` 的插件注册机制发现。`PlatformEntry` 数据类声明名称、标签、适配器工厂、被动依赖探测（`check_fn`，侧效应自由）和主动依赖安装器（`ensure_deps_fn`，仅在平台实际启用时触发）。`sparkii setup` 和 `sparkii status` 命令使用被动探测展示平台就绪状态，`create_adapter()` 在被动探测失败时调用主动安装器。日志噪声过滤通过 `_TELEGRAM_NOISY_STATUS_RE` 正则抑制瞬态状态消息，避免技术细节泄露到用户聊天。
