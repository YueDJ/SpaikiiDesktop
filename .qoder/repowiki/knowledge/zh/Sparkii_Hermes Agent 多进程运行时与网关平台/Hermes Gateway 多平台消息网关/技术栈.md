网关核心运行时基于 Python asyncio 事件循环驱动，`gateway/run.py`（约 27,934 行）是整个文件中最大的单一模块，协调平台适配器连接、会话生命周期、消息投递与 Agent 缓存管理。平台适配器通过 HTTP/WebSocket/SMS 等协议接入，支持 Telegram、Discord、WhatsApp、Weixin、Signal、Slack、Mattermost、Matrix、Feishu、WeCom、DingTalk、Email、SMS、Home Assistant、API Server、Webhook 等 20+ 内置平台，以及通过 `gateway/platform_registry.py` 的插件机制动态注册的第三方平台（如 IRC）。每个平台在 `Platform` 枚举中声明，插件平台通过 `_missing_()` 动态创建成员。

会话管理由 `gateway/session.py`（约 3931 行）实现，`SessionStore` 持久化会话到磁盘，`SessionContext` 跟踪消息来源（平台、chat_id、thread_id、sender_id）。重置策略（`SessionResetPolicy`）评估何时开启新对话。配置系统（`gateway/config.py`，约 2694 行）从 `config.yaml` 加载并验证网关配置，支持平台启用/禁用、家庭频道、流式输出模式（auto/off/SSE/WebSocket）、会话重置策略等。多路复用 profile 支持通过 `GATEWAY_MULTIPLEX_PROFILES` 环境变量与 config.yaml 联合控制。

消息投递由 `gateway/delivery.py`（约 647 行）路由，支持显式目标（`telegram:123456`）、平台家庭频道、来源回溯（`origin`）和本地文件保存四种模式。`DeadTargetRegistry` 跟踪已失效的投递目标（如被踢出的群组），避免重复发送。长消息截断上限 4000 字符（Telegram API 限制 4096），原生分块适配器绕过此限制。SSE/WebSocket 流式输出由 `gateway/display_config.py` 控制，支持按平台独立配置。Windows 环境依赖 `sparkii_bootstrap` 在启动时配置 UTF-8 stdio 以正确处理非 ASCII 字符。
