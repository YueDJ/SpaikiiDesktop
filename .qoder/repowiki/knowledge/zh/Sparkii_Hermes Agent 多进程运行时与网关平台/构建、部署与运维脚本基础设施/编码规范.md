- 容器启动流程采用分层 shim：`entrypoint-dispatch.sh` 检测 PID 1 后委派给 s6-overlay `/init`，非 PID 1 时回退为直接执行 stage2 hook + main wrapper，保证在不同运行时行为一致。
- Docker 内服务通过 `s6-rc.d/<service>/run`、`type`、`dependencies.d/base` 声明式定义，新增服务需复制模板并注册到 `user/contents.d/`。
- Nix 包通过 `perSystem` 暴露，并以 `minimal` 为基础用 `extraDependencyGroups` 叠加可选特性（如 messaging、voice、matrix），形成最小镜像到全量镜像的派生关系。
- CI 脚本集中在 `scripts/ci/`，每个 PR 相关动作（review comment、变更分类、E2E 截图、lockfile diff、timings report）拆分为单一职责的 Python 脚本并由 GitHub Actions 单独调用。
- Node.js 子项目（如 whatsapp-bridge）自带独立 `package.json` 与 `*.test.mjs` 测试文件，与主仓库解耦，可通过其自身 npm 工作区独立安装与测试。
- 跨平台安装器 (`install.sh` / `install.ps1` / `install.cmd`) 统一通过解析 `--branch`、`--commit`、`--dir`、`--sparkii-home`、`--ensure` 等长选项控制行为，并在 root 模式下自动切换到 FHS 布局。
