本模块按用途划分为三个并列子目录，彼此无代码依赖，仅通过约定路径被仓库其他部分调用：
- `scripts/`：扁平的 Python/shell/PowerShell 工具集，按功能再分 `ci/`（PR 评论、变更分类、E2E 截图状态、锁文件 diff、计时报告）、`observability/`（网关健康探针、OpenTelemetry 采集）、`sandbox/`（本地代理、SSH shim、stage2 运行器）、`tests/`（install.ps1 兼容性测试）、`toolperf_abeval/`（AB 评测）和独立的 `whatsapp-bridge/`（Node.js 桥接服务，含独立 package.json 与 .test.mjs 用例）。顶层脚本覆盖安装 (`install.sh/install.ps1/install.cmd`)、发布 (`release.py`)、基准测试、配置迁移、贡献者审计等一次性任务。
- `docker/`：基于 s6-overlay 的容器化方案。`entrypoint-dispatch.sh` 作为 PID 1 分发器，在 PID 1 场景下委派给 `/init` + `main-wrapper.sh`，在非 PID 1 场景下直接执行 `stage2-hook.sh` 并 exec main wrapper；`entrypoint.sh` 是向后兼容的废弃 shim，转发到 stage2 hook。`cont-init.d/` 与 `s6-rc.d/` 分别负责启动前权限/配置调和以及 dashboard、main-sparkii、user 三类服务的声明式生命周期管理。
- `nix/`：使用 uv2nix + pyproject-nix 构建 Python 包，`packages.nix` 暴露 `minimal`/`full`/`messaging`/`tui`/`web`/`desktop`/`sandbox` 等 Nix package，并通过 `perSystem` 钩入多平台；`devShell.nix` 汇总所有 npm workspace 的 `packageJsonPath`，统一生成 lockfile 并注入 Playwright/cage/ghostty 等 E2E 依赖；其余 `.nix` 文件分别封装 node-gyp、npm、Python、TUI、Web、桌面端及 NixOS module。
依赖方向单向：脚本不反向引用应用源码，仅通过命令行参数与环境变量驱动；Docker 层通过 s6 service 名与 cont-init 编号编排；Nix 层通过 `inputs'` 与 `passthru` 暴露开发期工具链。
