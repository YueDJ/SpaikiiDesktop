ACP Agent 适配器（cp_adapter/）将 Sparkii Agent 的全部能力通过 Agent Client Protocol（ACP）暴露给编辑器和 IDE 客户端，使外部工具（如 VS Code、JetBrains 等支持 ACP 的编辑器）能够通过标准协议驱动智能体。

核心服务由 server.py（2485 行）中的 HermesACPAgent(acp.Agent) 类实现，继承并实现 ACP 协议的全部方法。入口由 entry.py（283 行）的 CLI（python -m acp_adapter.entry / sparkii acp / sparkii-acp）负责：加载 ~/.sparkii/.env 环境变量、配置日志到 stderr（保留 stdout 给 ACP JSON-RPC 传输）、启动后台 MCP 工具发现线程，并通过 cp.run_agent(agent, use_unstable_protocol=True) 启动事件循环。模块还实现了 benign probe method 过滤器，静默处理客户端的 ping/health/healthcheck 存活探测，避免无害的 -32601 响应产生日志噪声。

session.py（685 行）的 SessionManager 维护内存中的 AIAgent 实例映射，并通过 sparkii_state.SessionDB 持久化到 ~/.sparkii/state.db，支持 create/fork/list/load/resume/delete/cleanup 全生命周期。会话恢复时从数据库重建完整对话历史，使编辑器重连后无缝继续。Windows/WSL 路径通过 	ranslate_cwd_for_wsl_backend() 做双向转换，确保跨平台一致性。

	ools.py（1347 行）维护 sparkii 工具名到 ACP ToolKind 的映射表（TOOL_KIND_MAP，覆盖 read_file→read、write_file/patch→edit、terminal/process→execute、web_search→fetch、browser_*→execute/read、delegate_task→execute、_thinking→think 等），并为每个工具提供专用的结果格式化函数，统一输出为 ACP 文本/diff/content block。

permissions.py（183 行）将 Sparkii 的危险命令审批桥接到 ACP equest_permission，构建 Allow once/Allow for session/Allow always/Deny/Deny always 五级选项集，超时（默认 60 秒）或异常回退为 deny。edit_approval.py（339 行）基于会话模式（default/accept_edits/dont_ask）实现文件编辑的预执行审批，对 .env、id_rsa 等敏感文件强制询问。events.py（279 行）通过工厂函数生成 AIAgent 回调，使用 safe_schedule_threadsafe 从工作线程安全投递 ACP session_update 到主事件循环。uth.py（79 行）动态注册终端设置方法与当前 provider 认证方式。provenance.py（127 行）根据 parent_session_id / end_reason 推导压缩链根节点，注入 ACP session 元数据。
