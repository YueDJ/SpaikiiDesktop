本模块是 Sparkii/Hermes 的插件仓库，按能力域划分子目录：
- `model-providers/<provider>/`：每个子目录实现一个 `ProviderProfile`（继承自 `providers.base.ProviderProfile`），在模块末尾实例化并通过 `register_provider()` 向宿主注册，由 `plugin.yaml` 声明 name/kind/version。
- `platforms/<channel>/`：每个聊天/平台（slack、telegram、discord、teams、whatsapp、matrix、dingtalk、feishu、google_chat、irc、line、mattermost、sms、simplex、raft、a2a、buzz、homeassistant、ntfy、photon、wecom）实现 `adapter.py` 中的 `register(ctx)`，由 `__init__.py` 统一导出。
- `web/<engine>/`、`browser/<engine>/`、`image_gen/<engine>/`、`video_gen/<engine>/`：分别实现 `WebSearchProvider`、`BrowserProvider`、图像/视频生成后端，遵循相同的 provider ABC + `get_setup_schema()` + `is_available()` 模式。
- `memory/<store>/`：实现 `agent.memory_provider.MemoryProvider` ABC（如 holographic、hindsight、mem0、honcho、byterover 等），通过 `register(ctx)` 调用 `ctx.register_memory_provider(...)` 暴露给 agent。
- `dashboard_auth/<scheme>/`、`cron_providers/<impl>/`、`observability/<impl>/`、`security-guidance/`、`spotify/`、`teams_pipeline/`、`disk-cleanup/`、`google_meet/`：各自以独立 Python 包形式存在，通过 `plugin.yaml` 描述元数据并由宿主加载。
- 共享基础设施位于根级 `plugin_utils.py`，提供线程安全的 `lazy_singleton` 装饰器与 `SingletonSlot` 类，用于避免多进程/多线程下重复初始化外部客户端导致的资源泄漏。
依赖方向单向指向宿主：插件仅 import `agent.*`、`providers.*`、`tools.*`、`sparkii_cli.*` 等宿主 API，不反向被宿主以外的代码引用；各插件之间相互隔离，通过 `plugin.yaml` 和宿主插件发现机制装配。
