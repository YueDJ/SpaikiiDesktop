文件操作工具集为 LLM Agent 提供跨终端后端的统一文件操作能力，所有操作通过 shell 命令表达以适配不同执行环境。

文件操作引擎（`file_operations.py`，约 2960 行）定义 `ShellFileOperations` 类，封装文件读取、写入、搜索与补丁操作。写入路径安全由 `agent/file_safety.py` 的 `build_write_denied_paths()` 和 `build_write_denied_prefixes()` 保护，阻止写入系统敏感文件（如 `~/.ssh/`、`~/.gnupg/` 等）。终端输出中的 fence 泄漏（OSC 序列、`__SPARKII_FENCE_*__` 标记）由 `_strip_terminal_fence_leaks()` 自动清理。行尾检测（`_detect_line_ending`）确保跨平台写入一致性。

文件工具层（`file_tools.py`，约 2622 行）实现 Agent 可调用的 `read_file`、`write_file`、`search_files` 等工具。`read_file` 有字符数上限保护（默认 100,000 字符，可通过 `config.yaml` 的 `file_read_max_chars` 配置），超限内容通过 `_truncate_to_char_budget()` 按行边界截断并提供 `next_offset` 续读。`~` 展开使用 `get_subprocess_home()` 确保 gateway 进程中与 CLI 交互会话中路径解析一致。

代码执行工具（`code_execution_tool.py`，约 2078 行）实现 Programmatic Tool Calling (PTC)，允许 LLM 编写 Python 脚本通过 RPC 调用 Sparkii 工具，将多步工具链折叠为单次推理。本地后端通过 Unix Domain Socket（Windows 上降级为 loopback TCP）实现父子进程 RPC；远程后端（Docker/SSH/Modal/Daytona）通过文件轮询实现请求-响应。沙箱安全严格：`SANDBOX_ALLOWED_TOOLS` 白名单限制仅 7 个工具可用，`_scrub_child_env()` 按秘密子串（KEY/TOKEN/SECRET 等）过滤环境变量，Windows OS 必需变量（SYSTEMROOT/COMSPEC 等）通过精确名称白名单放行。stdout 截断采用 head/tail 策略（40%/60% 分配，总计 50KB 上限）。

工作区变更快照（`working_diff.py`，约 132 行）为 `/diff` 斜杠命令提供表面无关的 git diff 收集逻辑，支持 working/staged/all 三种模式，未跟踪文件通过 `git diff --no-index /dev/null <file>` 折叠为新增差异。Git 操作有 15 秒超时保护，未跟踪文件数量上限 50 个。
