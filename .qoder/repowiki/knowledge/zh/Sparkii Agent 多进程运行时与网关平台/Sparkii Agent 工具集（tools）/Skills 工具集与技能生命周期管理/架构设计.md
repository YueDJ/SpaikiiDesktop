本模块按职责拆分为多个独立 Python 文件，围绕 `~/.sparkii/skills/` 这一单一事实源组织：
- 运行时入口与渐进式披露：`skills_tool.py` 暴露 `skills_list` / `skill_view` 等 agent 工具，实现元数据缓存（基于目录 mtime + TTL）与插件技能桥接。
- Hub 注册中心：`skills_hub.py` 定义 `SkillSource` ABC 及 `GitHubSource`，通过 `GitHubAuth`（PAT / gh CLI / GitHub App JWT RS256）从多 tap 仓库拉取技能并构建 `SkillBundle`，配合 `.hub/quarantine`、`audit.log`、`taps.json`、`index-cache` 等状态目录。
- 安全与合规：`skills_guard.py` 用正则模式库对下载后的技能做静态扫描，输出 `ScanResult`；`skill_linter.py` 执行更宽松的约定检查（命名、描述营销词、POSIX 限制、废弃文件等），二者均返回 advisory 结果由调用方决策。
- 同步层：`skills_sync.py` 负责将 bundled/optional skills 按 v2 manifest 增量复制到用户目录；`skills_sync_client.py` 实现内容寻址的 wire protocol（blob/tree/commit + CAS ref），维护 `sync-manifest` 跨设备 opt-in 状态。
- 写入治理：`skill_manager_tool.py` 是 agent 可调用 create/edit/patch/delete/write_file/remove_file 的统一入口，内置路径遍历防护、删除目标校验、pinned/org-mirror/background-review 等多层守卫，并在写后触发 guard 扫描。
- 可观测性与溯源：`skill_usage.py` 维护 `.usage.json` 侧边栏记录活跃/陈旧/归档状态与活动计数，带进程级文件锁；`skill_provenance.py` 通过 `contextvars.ContextVar` 标记当前写入来源（foreground vs background_review），供 curator 自治流程区分所有权。
- 深度诊断：`skills_ast_audit.py` 基于 `ast` 模块对 Python 技能进行动态导入/属性访问模式的可选审计。
依赖方向单向向下：上层工具（manager/hub/tool）依赖 guard/linter/sync/provenance/usage，guard 不反向依赖其他工具。
