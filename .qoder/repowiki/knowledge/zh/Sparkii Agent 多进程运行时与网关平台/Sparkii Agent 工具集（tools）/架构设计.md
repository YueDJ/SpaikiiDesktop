所有子模块通过 `tools.registry.ToolRegistry` 的 `register()` 在模块导入时自注册：每个工具文件声明 `(name, toolset, schema, handler, check_fn, requires_env, is_async, ...)`，由 registry 维护单例并对外提供 `get_definitions()`、`dispatch()`、`check_tool_availability()` 等接口。
- 启动期 `discover_builtin_tools()` 通过 AST 扫描 `tools/*.py` 中顶层 `registry.register(...)` 调用，仅 import 真正注册的工具模块，避免全量导入开销；结果缓存到 `$SPARKII_HOME/cache/tool_discovery_cache.json`。
- 运行时调度统一经 `registry.dispatch(name, args)`，自动桥接异步 handler、规范化结果为字符串或 `_multimodal` 信封、对异常做 JSON 错误封装与长度截断。
- 工具可用性按 toolset 分组并由 `check_fn` 探测（Docker/Modal/Playwright 等），TTL 30s + 最近成功 60s 宽限窗口，防止瞬时故障导致工具静默消失；支持 profile 级缓存隔离。
- 插件覆盖受控：`override=True` 需 operator opt-in，且通过 `handler.__globals__['__name__']` 绑定到插件命名空间，禁止跨插件篡改内置工具。
- 两个子包 `computer_use/`（CUI/视觉路由后端）和 `environments/`（Docker/Modal/Singularity/SSH/Vercel 沙箱）作为可插拔后端被上层工具按需选用，不直接参与 registry 注册。
- 共享基础设施集中在本层：`budget_config`、`tool_output_limits`、`tool_result_storage`、`hook_output_spill`、`lazy_deps`、`schema_sanitizer`、`path_security`、`interrupt`、`thread_context` 等被各工具子模块复用。
