TUI Gateway 是 Sparkii 的 JSON-RPC 服务端（	ui_gateway/server.py，约 14278 行），支持 stdio 与 WebSocket 两种传输模式，是 TUI 终端界面、浏览器 Dashboard 和桌面应用与 Agent 交互的统一后端。

传输抽象层（	ransport.py，220 行）定义 Transport Protocol，提供三种实现：StdioTransport（写 sys.stdout，带 	hreading.Lock 保护和 peer-gone 错误检测）、TeeTransport（主通道 + 侧车 WS 广播，副通道 best-effort 不影响主路径）、WSTransport（ws.py 中的 per-connection 实现，支持 token 帧合并与事件循环安全调度）。通过 contextvars.ContextVar 绑定当前请求的 transport，使所有 handler 代码与 I/O 完全解耦。

核心逻辑集中在 server.py：维护全局 _sessions（会话状态）、_methods（RPC 方法注册表）、_pending（待响应请求）、_answers（应答缓存）、数据库句柄等共享状态。方法按职责拆分到 methods_session.py（3295 行，会话 CRUD 与恢复）、methods_config.py（426 行，配置读写）、methods_prompt.py（997 行，提示发送与审批）、methods_tools.py（1947 行，工具管理）、methods_complete.py（514 行，补全）等文件，通过 method_ctx.HandlerRegistry 的装饰器注册。长耗时 handler（_LONG_HANDLERS 集合）路由到 ThreadPoolExecutor 工作池执行，快速路径保留在主线程以维持消息顺序。

WebSocket 接入（ws.py，477 行）提供 handle_ws(ws) 协程，复用同一套 dispatch 与所有 handler。连接接受后立即发送 gateway.ready 事件。WS 孤儿会话通过 _ws_orphan_reap_grace（默认 20 秒）自动回收，防止浏览器刷新导致的进程泄漏。辅助子系统包括：git_probe.py（Git 仓库探测）、project_tree.py（项目树渲染）、ender.py（流式渲染）、event_publisher.py（WS 事件发布）、	urn_marker.py（转轮标记）、_stdin_recovery.py（stdin EOF 恢复）等。
