网关核心运行时基于 Python asyncio 事件循环驱动，`gateway/run.py`（约 27,934 行）是整个文件中最大的单一模块，协调 Agent 与 20+ 消息平台之间的完整交互生命周期。`GatewayRunner` 类管理网关的启动、运行与优雅关闭。

会话路由是核心职责。每条入站消息通过 `gateway/session.py` 的 `SessionStore` 映射到持久化会话（`SessionContext` 包含平台、chat_id、thread_id、sender_id），会话存储到磁盘确保跨重启连续性。`get_or_create_session()` 根据消息来源查找或创建会话，`auto_continue_freshness_window()` 控制中断会话的自动恢复窗口（默认 1 小时）。重置策略评估何时开启新对话上下文。

Agent 缓存管理防止长运行网关的内存膨胀。Per-session AIAgent 以 LRU 顺序缓存（上限 `_AGENT_CACHE_MAX_SIZE=128`），空闲超过 `_AGENT_CACHE_IDLE_TTL_SECS`（1 小时）的 Agent 被驱逐。`gateway/agent_cache_pressure.py` 提供基于内存压力的额外清理阀。每个 Agent 实例持有 LLM 客户端、工具 Schema、记忆提供者等资源。

消息投递通过 `gateway/delivery.py` 的 `DeliveryRouter` 路由到目标平台适配器。`resolve_delivery_transport()` 解析逻辑平台到实际传输层（原生适配器优先，Relay 适配器作为备选）。`completion_queue` 消费机制在 Agent 空闲时轮询异步委托完成事件和 cron job 输出，注入为新用户/内部轮次。会话卫生（hygiene）压缩处理过长对话：`hygiene_compaction_recovered()` 评估压缩是否实际缩减了上下文，失败时通过乘法阶梯（x1/x3/x9）递增冷却间隔，上限 1 小时。平台连接超时默认 30 秒（Telegram 180 秒），适配器断开超时 5 秒。SSE 代理缓冲上限 16MB。信号处理（SIGINT/SIGTERM）触发优雅关闭：停止接受新消息、等待进行中的轮次完成、断开所有适配器。
