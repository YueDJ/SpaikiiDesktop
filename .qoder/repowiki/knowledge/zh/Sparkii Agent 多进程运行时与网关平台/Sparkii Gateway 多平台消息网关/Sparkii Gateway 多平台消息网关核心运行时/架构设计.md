模块以 `run.py` 中的 `GatewayRunner` 为进程入口，负责启动所有已配置的平台适配器、调度 agent turn、处理压缩/恢复/健康检查等运行时循环；`platforms/base.py` 定义 `BasePlatformAdapter` 抽象基类（connect/disconnect/send/get_chat_info 等），各具体平台（`platforms/qqbot/`、`yuanbao*`、`signal`、`weixin`、`whatsapp_*`、`bluebubbles`、`msgraph_webhook` 等）继承该基类实现协议细节，并通过 `platforms/__init__.py` 的 PEP 562 延迟导入避免冷启动开销。

数据流分层：入站事件经 adapter → `session.py` 的 `SessionStore`/`SessionContext` 解析并持久化到 sparkii_state；出站响应经 `delivery.py` 的 `DeliveryRouter`/`DeliveryTransport` 按目标平台路由，必要时走 `relay/adapter.py` 的 `RelayAdapter` 通过 connector 转发给后端真实平台。

横向横切能力由独立文件提供：`config.py`、`display_config.py` 统一配置读取；`streaming_tts_consumer.py`、`stream_consumer.py`、`stream_dispatch.py`、`turn_lease.py` 处理流式 TTS 与 turn 级并发控制；`shutdown_*`、`restart_loop_guard.py`、`scale_to_zero.py`、`memory_monitor.py`、`agent_cache_pressure.py` 构成优雅关停、重启保护、弹性伸缩与内存压力回收；`rich_sent_store.py`、`lifecycle_ledger.py`、`delivery_ledger.py` 提供幂等发送与生命周期审计；`slash_commands.py`、`slash_access.py`、`authz_mixin.py` 实现命令与授权。依赖方向单向：`run.py` → `platforms.*` / `session` / `delivery` / `relay`，各 platform 仅依赖 `base` 与共享工具，不反向引用 runner。
