Sparkii CLI 核心模块是 Sparkii Agent 命令行工具的基础设施层，承担命令注册、配置管理、认证凭据处理、模型提供者切换、插件生命周期、会话持久化与 Web/代理服务等核心职责。该层位于 `sparkii_cli/` 目录下，为上层的 CLI 入口（`main.py`）和所有子命令处理函数提供统一的抽象接口。

核心模块的设计遵循"单一数据源"原则：命令定义集中于 `commands.py` 的 `COMMAND_REGISTRY`，配置读取统一通过 `config.py` 的 `cfg_get()` 函数，凭据管理归口于 `auth.py` 与 `credential_lifecycle.py`。这种集中化设计使得 CLI 帮助文本、Gateway 消息平台命令列表、Tab 自动补全、Telegram BotCommands 等多个消费者可以从同一注册表派生数据，避免了分散定义导致的不一致。

模块间依赖关系清晰：`config.py` 是最底层的依赖，几乎所有模块都需要读取配置；`auth.py` 依赖 `config.py` 获取凭据存储路径；`commands.py` 依赖 `prompt_toolkit`（可选）提供补全能力，但核心的 `resolve_command()` 和 `COMMAND_REGISTRY` 不依赖任何可选库。`sqlite_runtime.py` 为会话管理提供独立的数据库层，与配置层无循环依赖。

该层还承载了跨平台兼容性处理：`_subprocess_compat.py` 封装 Windows 的 `CREATE_NO_WINDOW` 标志与 `platform._syscmd_ver` 控制台抑制，`pty_bridge.py`/`win_pty_bridge.py` 分别处理 Unix PTY 与 Windows ConPTY 的交互式终端桥接。`_early_recovery.py` 实现 venv 自修复，在损坏的虚拟环境中仍能完成最基本的模块导入。
