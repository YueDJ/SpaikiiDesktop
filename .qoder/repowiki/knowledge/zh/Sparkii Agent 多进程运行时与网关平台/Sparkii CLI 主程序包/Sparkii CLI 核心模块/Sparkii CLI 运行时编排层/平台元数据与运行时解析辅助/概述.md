平台元数据与运行时解析辅助模块由 platforms.py、untime_provider.py 和 sqlite_runtime.py 三个文件组成，为 Sparkii 的跨平台运行提供基础设施。

platforms.py（85 行）是平台注册表的单一真相来源，通过 PlatformInfo NamedTuple 和 PLATFORMS OrderedDict 集中声明所有内置消息平台（CLI、Telegram、Discord、Slack、WhatsApp、Signal、BlueBubbles、Email、Home Assistant、Mattermost、Matrix、DingTalk、飞书、企业微信、微信、QQBot、Yuanbao、Webhook、API Server、Cron），每个平台关联显示标签和默认工具集名称。platform_label() 和 get_all_platforms() 函数在内置平台基础上合并插件动态注册的平台（通过 gateway.platform_registry），确保 	ools_config 和 skills_config 的平台菜单始终完整。

untime_provider.py（2298 行）是运行时提供商解析的核心引擎，被 CLI、Gateway、Cron 和各种辅助模块共享。它整合了 uth.py（认证注册表与凭据解析）、credential_pool.py（多凭据池与故障切换）、providers.py（提供商身份与覆盖层）、config.yaml（用户配置）四个数据源，实现从模型选择到实际 API 调用的完整解析管线。关键功能包括：_getenv() 通过 secret_scope.get_secret 实现 profile 感知的环境变量读取（多路复用场景下避免跨 profile 凭据泄漏）；_detect_api_mode_for_url() 自动检测 API 模式（OpenAI Chat、Anthropic Messages、Codex Responses）以匹配不同端点的协议要求；_config_base_url_trustworthy_for_bare_custom() 防止过时的 base_url 劫持本地 custom 提供商会话。

sqlite_runtime.py（124 行）提供零依赖的 SQLite 运行时检测工具，在安装器和更新代码中使用（早于第三方依赖加载）。probe_sqlite_runtime() 通过子进程方式探测指定 Python 解释器的 SQLite 版本信息，返回 SQLiteRuntimeInfo dataclass，包含版本号、source ID 和 WAL-reset 漏洞检测（SQLite 3.7.0 至 3.51.3 之间的特定版本存在 WAL 文件损坏 bug）。探测脚本通过清除 CONDA_PREFIX、PYTHONPATH、VIRTUAL_ENV 等环境变量确保测量的是解释器原生链接的 SQLite 而非虚拟环境注入的版本。
