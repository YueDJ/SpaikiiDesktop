模型目录、提供商解析与模型切换核心模块由 model_catalog.py、model_switch.py 和 providers.py 三个文件组成，构成 Sparkii 从模型选择到 API 调用的完整解析管线。

model_catalog.py（472 行）实现远程模型目录的获取、验证与缓存。Sparkii 文档站托管一个 JSON 格式的模型清单（model-catalog.json），包含 OpenRouter 和 Nous Portal 等提供商的精选模型列表，允许不发版即可更新模型推荐。获取管线采用三级缓存策略：进程内缓存（TTL 失效）、磁盘缓存（~/.sparkii/cache/model_catalog.json）、远程获取（主 URL + fallback URL 链）。过期磁盘缓存通过 stale-while-revalidate 模式异步刷新，确保交互式界面（如模型选择器）永不阻塞于网络请求。清单格式为 version 1 schema，支持 providers 块内嵌自由元数据，未知字段自动忽略。get_curated_openrouter_models() 和 get_curated_nous_models() 提供类型化的访问器，失败时返回 None 让调用方回退到硬编码列表。seed_cache_from_checkout() 支持 sparkii update 后直接用本地检出的清单预热缓存。

providers.py（960 行）是提供商身份的单一真相来源，合并两个数据层：models.dev 目录（109+ 提供商的 base URL、环境变量、显示名、模型元数据）和 Sparkii 覆盖层（SparkiiOverlay dataclass，补充传输类型、认证模式、聚合器标志、额外环境变量等 models.dev 不跟踪的元数据）。ProviderDef dataclass 在运行时将两层合并为统一视图。关键功能包括：esolve_provider_full() 完整解析提供商身份、is_aggregator() 判断是否为聚合器（如 OpenRouter）、determine_api_mode() 根据提供商和 base URL 确定 API 协议模式、custom_provider_aliases() 处理自定义提供商别名。

model_switch.py（3368 行）是 CLI 和 Gateway /model 命令共享的核心管线：解析标志 → 别名解析 → 提供商解析 → 凭据解析 → 模型名标准化 → 元数据查找 → 构建结果。提供商切换使用 --provider 标志，冒号语法保留给 OpenRouter 变体后缀（:free、:extended、:fast）。模块整合 gent.models_dev（模型能力、上下文窗口、成本信息）、providers.py（提供商身份）和 model_normalize.py（按提供商的模型名格式化）三个基础层。_declared_model_ids() 支持从多种配置形状（dict、list、string、list-of-dicts）中提取模型 ID。
