模块由三个职责清晰的文件组成：
- `main.py` 是进程入口，承担冷启动优化（`_startup_fast` 快速路径、`_early_recovery` venv 自愈、UTF-8 stdio 设置）、配置文件早期读取（`config.yaml` → `SPARKII_REDACT_SECRETS`/`force_ipv4`）、Profile 覆盖（`--profile/-p` 在 argparse 之前解析并改写 `SPARKII_HOME`）、日志初始化、Termux/TUI 早判、以及通过大量 `from sparkii_cli.subcommands.* import build_*_parser` 动态组装子命令树，最终将每个子命令绑定到对应的 `cmd_*` 处理器。
- `_parser.py` 仅维护顶层 `argparse.ArgumentParser` 与 `chat` 子解析器，并通过 `_inherited_flag` + `PRE_ARGPARSE_INHERITED_FLAGS` 标记可在 relaunch 时透传的 flag，使其他模块可独立 introspect 而不触发完整启动。
- `commands.py` 以不可变 `CommandDef` dataclass 集中声明所有斜杠命令，构建 `COMMAND_REGISTRY` 并在导入时派生 `_COMMAND_LOOKUP`、`COMMANDS`、`SUBCOMMANDS`、`GATEWAY_KNOWN_COMMANDS`、`ACTIVE_SESSION_BYPASS_COMMANDS` 等只读视图；同时提供 `resolve_command`、`is_gateway_known_command`、`telegram_bot_commands`、`gateway_help_lines` 等面向 gateway/Telegram/Discord 的导出接口，并通过 `execute` 字段引用共享执行器实现纯文本输出。
依赖方向单向：`main.py` 依赖 `_parser.py` 与 `commands.py`；`commands.py` 仅依赖配置与插件发现，不反向依赖入口。
