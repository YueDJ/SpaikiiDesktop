插件系统、技能中心与工具配置模块的技术栈围绕 Python 的可扩展性机制与声明式配置构建。

插件发现层面，plugins.py 利用 Python 标准库的 importlib.metadata 扫描 pip 安装包暴露的 sparkii_agent.plugins entry-point 组，同时通过文件系统扫描 plugins/（bundled）、~/.sparkii/plugins/（user）和 .sparkii/plugins/（project）三个目录。每个目录插件必须包含 plugin.yaml 清单文件（YAML 格式，由 PyYAML 解析）和 __init__.py 中的 egister(ctx) 入口函数。插件清单支持 manifest_version 字段用于向前兼容，当前支持版本为 1。模块使用 hashlib 对插件目录做指纹计算以检测变更。

技能中心层面，SKILL.md 文件是技能的声明式载体，兼容 agentskills.io 标准格式，使用 YAML frontmatter 声明 name、description、version、license、platforms、prerequisites、metadata 等字段。	ools/skills_hub.py（约 4430 行）与 	ools/skills_tool.py（约 2060 行）提供技能的搜索、安装、浏览与加载能力，支持 GitHub Contents API 远程获取与本地可选技能。技能索引缓存使用 TTL 1 小时的 index-cache 目录。

工具配置层面，	ools_config.py（约 5472 行）使用 click 风格的交互式终端 UI（通过 sparkii_cli/curses_ui.py 的 curses_checklist）实现工具集的可视化开关配置。配置持久化到 ~/.sparkii/config.yaml 的 platform_toolsets 键下。skills_config.py（203 行）提供类似的技能开关配置，支持全局禁用列表与按平台覆盖列表。两者共享 platforms.py 的平台注册表以确保菜单一致性。

运行时依赖包括：PyYAML（插件清单与配置解析）、Rich（Markdown 渲染与表格展示）、click 或 argparse（CLI 子命令注册）。插件系统本身不依赖任何框架级基础设施，仅通过 PluginContext 暴露的注册 API 与宿主交互。
