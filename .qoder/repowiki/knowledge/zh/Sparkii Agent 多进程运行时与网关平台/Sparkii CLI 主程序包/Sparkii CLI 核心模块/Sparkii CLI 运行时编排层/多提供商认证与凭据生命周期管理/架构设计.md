模块由三个互补文件组成，形成“注册表 + 运行时解析 + 生命周期协调”的分层结构：
- `sparkii_cli/auth.py` 是核心运行时：通过 `ProviderConfig` dataclass 和 `PROVIDER_REGISTRY` 集中声明所有推理提供商（Nous Portal、OpenAI Codex、xAI、Qwen、MiniMax、Anthropic、Gemini、Bedrock、Vertex、Azure Foundry、Spotify 等），按 `auth_type`（`oauth_device_code` / `oauth_external` / `oauth_minimax` / `api_key` / `aws_sdk` / `vertex` / `external_process`）分发；使用 `~/.sparkii/auth.json` 作为跨进程共享的认证状态存储，并通过 `fcntl`/`msvcrt` 实现平台无关的文件锁；提供 `resolve_provider()`、`resolve_*_runtime_credentials()` 等函数完成令牌刷新、端点探测（如 Z.AI 并行探针、Kimi 前缀路由）、错误格式化（`AuthError` + `format_auth_error`）。
- `sparkii_cli/credential_lifecycle.py` 是单一写入/删除入口，强制所有修改 `.env` 的路径同时更新 `credential_pool`（仅删除 `source == env:<VAR>` 的条目以保留 OAuth/device-code/manual/borrowed 凭证）和 `config.yaml` 中的镜像字段（`model.api_key`、`auxiliary.*.api_key`、`custom_providers[*].api_key`），并调用 `suppress_credential_source` / `unsuppress_credential_source` 控制池源抑制，避免 UI/TUI/Gateway 多入口导致的凭据不一致。
- `sparkii_cli/subcommands/auth.py` 仅负责 `argparse` 子命令装配（add/list/remove/reset/status/logout/spotify），将参数转发给上层处理逻辑，保持 CLI 入口与业务解耦。
依赖方向单向：subcommands → credential_lifecycle → auth（registry + store），auth 再反向被 credential_lifecycle 通过延迟 import 访问 `_auth_store_lock`/`_load_auth_store` 等内部 API，避免循环导入。
