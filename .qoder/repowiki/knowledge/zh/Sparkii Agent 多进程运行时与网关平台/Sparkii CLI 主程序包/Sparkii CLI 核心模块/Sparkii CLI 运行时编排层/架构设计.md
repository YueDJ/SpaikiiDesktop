以 `sparkii_cli/main.py` 为唯一进程入口，按严格顺序完成：① UTF-8 流修复与 `_startup_fast` 超快路径（版本、Termux、容器检测）；② 通过 `_apply_profile_override()` 在任意模块导入前解析 `-p/--profile` 并设置 `SPARKII_HOME`，使所有子模块共享同一配置根；③ 调用 `env_loader.load_sparkii_dotenv` 注入 `.env`，再经 `config.read_raw_config` 桥接 `security.redact_secrets` / `network.force_ipv4` 到环境变量；④ 初始化 `sparkii_logging` 文件日志；⑤ 从 `subcommands/*` 批量 `build_*_parser` 注册 argparse 子命令；⑥ 根据子命令分发到对应实现。

跨子模块协作契约：
- 配置链：`config_migration` 负责 YAML/.env/schema 迁移，被 `model_provider_setup`、`secrets_auth_integrations`、`plugins_skills_tools` 等共同消费；`platform_runtime_helpers` 提供平台/运行时元数据供各子命令复用。
- 认证与凭据：`secrets_auth_integrations` 暴露的 PROVIDER_REGISTRY、auth.json、.env 同步机制被 `main.py` 的 `_has_any_provider_configured()` 及各类 setup 流程调用。
- 模型与提供商：`model_provider_setup` 的模型目录缓存与提供商合并结果被 `main.py` 的模型选择向导（`model_setup_flows`）直接驱动。
- 插件/技能/工具：`plugins_skills_tools` 的发现与安装由 `main.py` 的 `tools`、`skills`、`mcp` 等子命令触发，并通过 `managed_scope` 注入管理员覆盖。
- 可观测性：`observability` 的 shared_metrics 订阅者由 gateway/dashboard 等长驻进程启动时接入，与 CLI 短生命周期进程解耦。
- Web/代理运行时：`proxy/`、`web_routers/`、`dashboard_auth/` 由 `gateway`、`dashboard`、`gui` 子命令拉起，共享 `route_identity`、`middleware`、`active_sessions` 等顶层状态。
