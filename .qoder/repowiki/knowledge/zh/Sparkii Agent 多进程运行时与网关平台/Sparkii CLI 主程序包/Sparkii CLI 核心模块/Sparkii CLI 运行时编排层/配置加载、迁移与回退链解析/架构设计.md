模块由三个文件构成清晰的职责分层：
- `config.py`（核心）：实现配置的持久化生命周期——路径解析（`get_config_path`/`get_env_path`）、目录初始化（`ensure_sparkii_home`，区分 managed/NixOS 与容器模式并设置 0700/0600 权限）、YAML 读取缓存（按 `(path, mtime_ns, size)` 键 + `threading.RLock` 串行化读写）、默认值深合并、环境变量展开、`.env` 写入白名单/黑名单校验（`_ENV_VAR_NAME_DENYLIST`）、配置结构校验（`validate_config_structure`）以及迁移入口（`check_config_version` → `migrate_config`）。同时提供自定义 provider 归一化（`_normalize_custom_provider_entry`、`providers_dict_to_custom_providers`）和 TLS/headers 注入辅助。
- `config_migrations.py`（表驱动迁移）：将原先嵌套在 `config.py` 中的巨型 `if current_ver < N:` 阶梯拆分为独立的 `_migrate_to_N(results, quiet)` 函数，集中注册于 `MIGRATIONS` 元组并按严格升序执行；通过 `_cfg()` 延迟引用 `sparkii_cli.config` 避免循环导入，每个步骤通过 `read_raw_config` + `_persist_migration` 直接操作磁盘状态，保证后续步骤可见前一步变更。支持最低版本门槛 `SUPPORT_FLOOR_VERSION = 12`，低于此版本的配置不再自动迁移。
- `fallback_config.py`（回退链解析）：独立的小工具层，从 `fallback_providers` / `fallback_model` 两个键聚合出最终的回退 provider 列表，去重依据是 `(provider, model, base_url)` 三元组，并通过 `agent.secret_scope.get_secret` 安全地解析 `key_env` 字段以适配多 profile 场景。
依赖方向单向：`config_migrations.py` → `config.py`（仅通过 `_cfg()` 延迟访问），`fallback_config.py` 不反向依赖另外两者，三者共同被上层 CLI/gateway 消费。
