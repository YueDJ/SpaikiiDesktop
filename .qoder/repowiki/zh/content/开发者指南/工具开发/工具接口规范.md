## 简介

Sparkii Agent的工具接口规范定义了工具注册、发现和执行的标准接口。所有工具必须遵循统一的接口规范，通过ToolRegistry注册表进行管理。本文档详细说明ToolEntry类的结构、egister()方法的参数规范以及工具注册的最佳实践。

## ToolEntry类结构

ToolEntry是工具元数据的核心数据类，定义在	ools/registry.py中：

## register()方法规范

egister()方法是工具注册的入口，必须在模块级别调用：

`python
def register(
    self,
    name: str,                    # 工具名称（必填）
    toolset: str,                 # 工具集名称（必填）
    schema: dict,                 # 函数Schema（必填）
    handler: Callable,            # 处理函数（必填）
    check_fn: Callable = None,    # 可用性检查（可选）
    requires_env: list = None,    # 所需环境变量（可选）
    is_async: bool = False,       # 异步标志（可选）
    description: str = ", # 描述（可选）
 emoji: str = , # emoji（可选）
 max_result_size_chars: int | float | None = None,
 dynamic_schema_overrides: Callable = None,
 override: bool = False, # 是否允许覆盖现有工具
):
`

### 参数详解

#### schema参数

Schema必须遵循OpenAI函数调用格式：

`json
{
 name: tool_name,
 description: 工具功能描述,
 parameters: {
 type: object,
 properties: {
 param1: {
 type: string,
 description: 参数说明
 }
 },
 required: [param1]
 }
}
`

#### handler参数

处理函数签名：
- 同步：def handler(args: dict, **kwargs) -> str
- 异步：sync def handler(args: dict, **kwargs) -> str

返回值必须是JSON字符串或包含_multimodal: True的字典。

## check_fn验证机制

check_fn用于验证工具的运行环境是否满足要求，支持TTL缓存和瞬态故障恢复：

`mermaid
flowchart TD
Start[调用check_fn] --> Cache{缓存命中?}
Cache --> |是| Return[返回缓存结果]
Cache --> |否| Execute[执行check_fn()]
Execute --> Result{结果?}
Result --> |True| CacheTrue[缓存True, 30s TTL]
Result --> |False| Grace{在宽限期内?}
Grace --> |是| ServeLastGood[返回上次True]
Grace --> |否| CacheFalse[缓存False]
CacheTrue --> ReturnTrue[返回True]
ServeLastGood --> ReturnTrue
CacheFalse --> ReturnFalse[返回False]
`

### 缓存配置

| 参数 | 值 | 说明 |
|------|-----|------|
| _CHECK_FN_TTL_SECONDS | 30s | 缓存有效期 |
| _CHECK_FN_FAILURE_GRACE_SECONDS | 60s | 瞬态故障宽限期 |
| _CHECK_FN_CACHE_MAX | 512 | 最大缓存条目数 |

## 完整示例

### 基础工具注册

`python
from tools.registry import registry, tool_error, tool_result

MY_TOOL_SCHEMA = {
 name: my_tool,
 description: 执行自定义操作,
 parameters: {
 type: object,
 properties: {
 input: {
 type: string,
 description: 输入数据
 }
 },
 required: [input]
 }
}

def my_handler(args: dict, **kwargs) -> str:
 try:
 input_data = args.get(input, )
 # 处理逻辑
 result = process(input_data)
 return tool_result(data={output: result})
 except Exception as e:
 return tool_error(f执行失败: {e})

registry.register(
 name=my_tool,
 toolset=custom,
 schema=MY_TOOL_SCHEMA,
 handler=my_handler,
 check_fn=lambda: os.getenv(MY_API_KEY) is not None,
 requires_env=[MY_API_KEY],
 description=自定义工具示例,
 emoji=🔧,
)
`

## 错误处理最佳实践

### 标准错误格式

所有工具错误必须使用 ool_error()返回：

`python
from tools.registry import tool_error

# 基础错误
return tool_error(文件未找到)

# 带额外信息的错误
return tool_error(操作失败, code=500, details=具体错误信息)
`

### 错误大小限制

- 错误消息最大2048字符（_MAX_TOOL_ERROR_CHARS）
- 超出部分自动截断并添加… [truncated]标记
- 日志保留最多8192字符用于调试

### 结果规范化

dispatch()方法自动规范化处理函数返回值：
- 字符串：直接返回（JSON格式）
- 多模态字典：包含_multimodal: True和content列表
- 其他类型：转换为错误消息
