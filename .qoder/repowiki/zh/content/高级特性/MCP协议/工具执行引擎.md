## 简介

工具执行引擎是 Sparkii Agent 的核心运行时组件，负责接收 AI 模型的工具调用请求并路由到正确的处理器。本文档详细说明执行引擎的内部机制，包括工具注册、调度执行、可用性检查和错误处理流程。

## 执行引擎架构

工具执行引擎采用集中式注册表模式，所有工具通过单例 ToolRegistry 统一管理：

## ToolRegistry 核心类

ToolRegistry 是工具执行引擎的核心，实现为模块级单例：

`python
class ToolRegistry:
    """Singleton registry that collects tool schemas + handlers from tool files."""
    
    def __init__(self):
        self._tools: Dict[str, ToolEntry] = {}
        self._plugin_override_policy: Dict[str, bool] = {}
        self._toolset_checks: Dict[str, Callable] = {}
        self._toolset_aliases: Dict[str, str] = {}
        self._lock = threading.RLock()
        self._generation: int = 0  # 变更计数器，用于缓存失效
`

## 工具调度流程

当 AI 模型发出工具调用请求时，执行引擎按以下流程处理：

`mermaid
sequenceDiagram
    participant LLM as AI 模型
    participant Executor as 工具执行器
    participant Registry as ToolRegistry
    participant Handler as 工具处理器
    
    LLM->>Executor: tool_call(name, args)
    Executor->>Registry: dispatch(name, args)
    
    alt 工具不存在
        Registry-->>Executor: error("Unknown tool")
    else 工具存在
        Registry->>Registry: get_entry(name)
        
        alt is_async = true
            Registry->>Handler: _run_async(handler(args))
        else is_async = false
            Registry->>Handler: handler(args)
        end
        
        Handler-->>Registry: result
        Registry->>Registry: _normalize_handler_result()
        Registry-->>Executor: normalized_result
    end
    
    Executor-->>LLM: tool_response
`

### dispatch 方法实现

`python
def dispatch(self, name: str, args: dict, **kwargs) -> str | dict:
    entry = self.get_entry(name)
    if not entry:
        return tool_error(f"Unknown tool: {name}")
    
    try:
        if entry.is_async:
            from model_tools import _run_async
            result = _run_async(entry.handler(args, **kwargs))
        else:
            result = entry.handler(args, **kwargs)
        return self._normalize_handler_result(name, result)
    except Exception as e:
        logger.exception("Tool %s dispatch error: %s", name, str(e))
        return tool_error(f"Tool execution failed: {type(e).__name__}: {e}")
`

## check_fn 可用性检查

工具注册时可以提供 check_fn 函数，用于在运行时验证工具是否可用（例如检查 Docker 是否运行、API 密钥是否配置）。

### TTL 缓存机制

为避免频繁调用外部检查，引擎实现了带 TTL 的缓存系统：

| 配置项 | 值 | 说明 |
|--------|-----|------|
| CHECK_FN_TTL_SECONDS | 30s | 缓存有效期 |
| CHECK_FN_FAILURE_GRACE_SECONDS | 60s | 瞬态故障宽限期 |
| CHECK_FN_CACHE_MAX | 512 | 最大缓存条目数 |

### 瞬态故障抑制

`python
def _check_fn_cached(fn: Callable) -> bool:
    now = time.monotonic()
    cache_key = (fn, scope)
    
    # 检查缓存
    with _check_fn_cache_lock:
        cached = _check_fn_cache.get(cache_key)
        if cached is not None:
            ts, value = cached
            if now - ts < _CHECK_FN_TTL_SECONDS:
                return value
    
    # 执行检查
    value = bool(fn())
    
    with _check_fn_cache_lock:
        if value:
            _check_fn_last_good[cache_key] = now
            _check_fn_cache[cache_key] = (now, True)
            return True
        
        # 检查是否在宽限期内
        last_good = _check_fn_last_good.get(cache_key)
        if last_good and now - last_good < _CHECK_FN_FAILURE_GRACE_SECONDS:
            return True  # 视为瞬态故障，保持可用
        
        _check_fn_cache[cache_key] = (now, False)
        return False
`

## 结果规范化处理

所有工具返回结果必须经过规范化，确保符合统一格式：

`python
def _normalize_handler_result(name: str, result):
    # 字符串结果：截断超长内容
    if isinstance(result, str):
        return _bound_json_error_result(result)
    
    # 多模态结果：图片、文件等
    if (isinstance(result, dict) 
        and result.get("_multimodal") is True
        and isinstance(result.get("content"), list)):
        return result
    
    # 不支持的类型：返回错误
    return tool_error(
        f"Tool handler returned unsupported result type: {type(result).__name__}",
        error_type="tool_result_contract"
    )
`

## 错误处理机制

执行引擎实现了多层错误处理：

### 异常捕获与净化

`python
try:
    result = entry.handler(args, **kwargs)
except Exception as e:
    logger.exception("Tool %s dispatch error: %s", name, str(e))
    raw = f"Tool execution failed: {type(e).__name__}: {e}"
    
    # 净化错误消息，移除可能导致 LLM 混淆的特殊字符
    from model_tools import _sanitize_tool_error
    sanitized = _sanitize_tool_error(raw)
    
    return tool_error(sanitized)
`

### 常见错误类型

| 错误类型 | 触发条件 | 处理方式 |
|----------|----------|----------|
| Unknown tool | 工具名称未注册 | 返回错误提示 |
| 	ool_result_contract | 返回类型不支持 | 返回错误提示 |
| Tool execution failed | handler 抛出异常 | 捕获并净化后返回 |

## 异步工具支持

对于需要异步操作的工具（如网络请求、文件 I/O），引擎自动桥接同步/异步边界：

`python
# 注册时标记为异步
registry.register(
    name="fetch_url",
    toolset="web",
    schema={...},
    handler=async_fetch_handler,
    is_async=True
)

# 调用时自动处理
if entry.is_async:
    result = _run_async(entry.handler(args, **kwargs))
`

### 变更计数器

`python
# 外部调用者可以缓存结果
if cached_generation == registry._generation:
    return cached_definitions
else:
    definitions = registry.get_tool_definitions()
    cached_generation = registry._generation
`

### 快照隔离

所有读操作使用快照，避免持锁时间过长：

`python
def _snapshot_entries(self) -> List[ToolEntry]:
    with self._lock:
        return list(self._tools.values())
`
